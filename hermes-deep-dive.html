01

为什么会有 Hermes Agent?

从 OpenClaw 到 Hermes — 一个关于自由与进化的故事

核心动机

2024 年，AI Agent 领域百花齐放，但几乎所有框架都有同一个问题：Agent 用完就忘，每次对话都是白板。Nous Research 想要一个能真正"成长"的 Agent — 它能从每次复杂任务中提炼经验，把经验变成可复用的技能，并在下次遇到类似问题时直接调用。这就是 Hermes 的起点。

打破模型锁定
市面上的 Agent 工具几乎都绑定特定模型（OpenAI、Anthropic）。Hermes 从第一天起就设计为完全模型无关 — 任何 OpenAI 兼容端点都能接入，200+ 模型随时切换。
闭环学习系统
传统 Agent 没有记忆，没有成长。Hermes 内置技能创建、技能自我改进、跨会话记忆、FTS5 会话搜索，形成完整的认知闭环。
不绑定你的笔记本
大多数 Agent 工具只能在本地运行。Hermes 支持 6 种终端后端（本地、Docker、SSH、Modal、Daytona、Singularity），可以部署在 $5 VPS 上，通过 Telegram 远程控制。
多平台统一入口
一个 Agent，15+ 平台同时在线。Telegram、Discord、Slack、WhatsApp、Signal、Matrix、Email、SMS、飞书、钉钉、微信、QQ Bot……全部共享同一个 Agent 实例。
研究级基础设施
Nous Research 是顶级开源模型研究机构。Hermes 内置批量轨迹生成和压缩，专门用于训练下一代工具调用模型。
MIT 完全开源
不是"开源核心 + 付费功能"的模式。Hermes 的全部功能都在 MIT 许可下开放，包括企业级功能如 Kanban 多 Agent 协作、Cron 调度器等。

发展时间线

OpenClaw 时代

Hermes 的前身 OpenClaw 是一个简单的 CLI Agent 包装器，功能有限，主要绑定 OpenAI API。

Hermes 诞生 — 技能系统

引入 Skills 系统：Agent 可以从复杂任务中自动创建 Markdown 技能文档，下次遇到类似问题直接加载。

Gateway 多平台网关

单一 Gateway 进程同时服务 Telegram、Discord、Slack 等平台，共享同一个 Agent 实例和会话历史。

插件化架构重构

内存提供商、模型提供商、工具全部插件化。核心代码不再包含任何特定提供商的硬编码逻辑。

TUI + Kanban + Cron（2025-2026）

引入 Ink/React TUI、SQLite Kanban 多 Agent 工作队列、内置 Cron 调度器、17k+ 测试套件。

03

核心对话循环

AIAgent.run_conversation() — 同步、可中断、预算感知的工具调用循环

run_conversation() 流程
01
检查中断 — _interrupt_requested 为 true 则 break 退出循环
02
检查预算 — budget.remaining > 0 或 _budget_grace_call（耗尽后有一次 Grace Call 收尾）
03
LLM API 调用 — client.chat.completions.create(model, messages, tools)
04
有工具调用? — 是: handle_function_call() 执行工具，结果追加到 messages，回到步骤 01
05
无工具调用 — 返回 response.content 作为最终文本响应
源码
# run_agent.py — 核心循环（简化版） while (api_call_count < self.max_iterations and self.iteration_budget.remaining > 0) \ or self._budget_grace_call: if self._interrupt_requested: break response = client.chat.completions.create( model=model, messages=messages, tools=tool_schemas ) if response.tool_calls: # 并行执行独立工具（最多 8 个 worker） for tool_call in response.tool_calls: result = handle_function_call(tool_call.name, tool_call.args, task_id) messages.append(tool_result_message(result)) api_call_count += 1 else: return response.content # 最终文本响应

关键设计

并行工具执行
_should_parallelize_tool_batch() 检测工具调用是否独立，独立则并发执行（最多 8 个线程）。路径重叠检测防止文件竞争。
预算追踪 + Grace Call
IterationBudget 追踪剩余轮次。预算耗尽后有一次 Grace Call，让 Agent 能优雅地总结而不是突然截断。
提示缓存保护
系统提示在整个对话中不可变。技能、工具、记忆的变更默认延迟到下次会话生效，避免缓存失效带来的高额费用。
持久化异步事件循环
每个线程维护一个长生命周期的 asyncio 事件循环，避免 httpx/AsyncOpenAI 客户端在 GC 时因"事件循环已关闭"报错。
04

核心亮点

让 Hermes 与众不同的设计决策

闭环学习系统

大多数 Agent 框架每次对话都是白板。Hermes 构建了一个完整的认知闭环：

技能创建
完成复杂任务后，Agent 自动将解决方案提炼为 Markdown 技能文档，存入 ~/.hermes/skills/
技能自我改进
每次使用技能时，Agent 可以 patch 改进它。技能会随使用而进化。
Curator 自动维护
后台 Curator 追踪技能使用频率，自动归档过时技能，保持技能库精简。
跨会话记忆
8 种可插拔记忆提供商（honcho、mem0、supermemory、byterover、hindsight、holographic、openviking、retaindb），FTS5 全文搜索历史会话。

三层插件系统

通用插件
实现 register(ctx)，可注册工具、CLI 子命令、生命周期钩子（pre/post_tool_call、pre/post_llm_call）。插件不得修改核心文件。来源：~/.hermes/plugins/ 和 pip entry points。
记忆提供商插件
实现 MemoryProvider ABC。内置：honcho、mem0、supermemory、byterover、hindsight、holographic、openviking、retaindb。新提供商必须作为独立 repo 发布。
模型提供商插件
每个推理后端是一个插件，调用 register_provider(ProviderProfile(...))。懒加载发现，用户插件覆盖内置插件（last-writer-wins）。28+ 提供商。

多 Agent 协作

delegate_task
父 Agent 同步等待子 Agent 完成。子 Agent 有独立的上下文和终端会话。支持批量并行（最多 3 个并发）。
Kanban
SQLite 支撑的看板，多个 Profile/Worker 协作处理共享任务。Board 硬隔离边界，Dispatcher 每 60s 认领任务，Heartbeat 防止超时误判。
# 单任务委派 delegate_task(goal="分析日志文件", context="...") # 批量并行（最多 3 个并发） delegate_task(tasks=[ {"goal": "测试模块A"}, {"goal": "测试模块B"}, {"goal": "测试模块C"}, ])

消息网关 — 15+ 平台统一接入

Telegram Discord Slack WhatsApp Signal Matrix Email SMS BlueBubbles Mattermost Feishu / 飞书 DingTalk / 钉钉 WeChat / 微信 WeCom / 企业微信 QQ Bot Yuanbao / 元宝 Home Assistant Webhook OpenAI API Server
双重消息守卫架构

当 Agent 正在运行时，消息经过两道守卫：(1) 基础适配器将消息放入 _pending_messages 队列；(2) Gateway Runner 拦截 /stop、/approve、/deny 等控制命令，直接内联分发而不走队列，避免竞态条件。

6 种终端后端

Local
直接在本地执行，最低延迟。
Docker
容器隔离，安全沙箱执行。
SSH
远程服务器执行，支持密钥认证。
Modal
Serverless 执行，空闲时几乎零成本。
Daytona

Hermes vs OpenClaw

Hermes 是 OpenClaw 的精神继承者，但已是完全不同量级的系统

维度 OpenClaw Hermes Agent
定位 CLI Agent 包装器 完整 Agent 运行时 + 平台
模型支持 主要 OpenAI/Anthropic 200+ 模型，28+ 提供商插件
平台 CLI 为主 CLI + TUI + 15+ 消息平台 + Web Dashboard
记忆系统 基础 MEMORY.md 8 种可插拔记忆提供商 + FTS5 会话搜索
技能系统 简单技能文件 自动创建 + 自我改进 + Curator 生命周期管理
多 Agent 无 delegate_task + Kanban 工作队列
调度 无 内置 Cron 调度器，自然语言时间表达式
终端后端 本地 本地 + Docker + SSH + Modal + Daytona + Singularity
插件系统 无 三层插件（通用 + 记忆 + 模型提供商）
提示缓存 不感知 一等公民，系统提示不可变，变更延迟生效
测试覆盖 有限 ~17k 测试，~900 文件，子进程隔离
迁移支持 — hermes claw migrate 一键迁移 OpenClaw 配置
供应链安全 无上界 所有依赖有上界，SHA 锁定，litellm 事件后加固
迁移路径

从 OpenClaw 迁移到 Hermes 只需一条命令：hermes claw migrate。它会自动导入 SOUL.md、记忆文件、技能、命令白名单、消息平台配置和 API 密钥。支持 --dry-run 预览，--preset user-data 仅迁移数据不迁移密钥。

Hermes vs Claude Code

两个都用 Ink/React 构建 TUI，但设计哲学截然不同

关于 Claude Code 源码

你的 claude/ 目录包含 Claude Code 的 TypeScript 源码（src/ 目录，约 500+ 文件）。这是 Anthropic 的官方 CLI 工具，用 TypeScript + React/Ink 构建，专注于代码编辑场景，与 Anthropic API 深度集成。

维度 Claude Code (Anthropic) Hermes Agent (Nous Research)
语言 TypeScript (全栈) Python (核心) + TypeScript (TUI)
TUI 框架 自研 Ink（内嵌在 src/ink/） 标准 Ink + React，通过 JSON-RPC 与 Python 通信
模型绑定 主要 Claude 系列（Anthropic API） 完全模型无关，200+ 模型
平台 CLI + IDE 插件（VS Code/JetBrains） CLI + TUI + 15+ 消息平台 + Web Dashboard
工具系统 每个工具一个目录（BashTool、FileEditTool 等） 注册表模式，自动发现，工具集组合
多 Agent AgentTool + Swarm（实验性） delegate_task + Kanban（生产就绪）
记忆 memdir（文件系统记忆） 8 种可插拔提供商 + FTS5 搜索
技能系统 Skills（基础） 自动创建 + 自我改进 + Curator
调度 ScheduleCronTool（基础） 完整 Cron 调度器，自然语言，多平台投递
插件系统 完整插件市场（DXT 格式） 三层插件系统（无市场，但更灵活）
权限系统 细粒度权限规则，沙箱模式 危险命令审批，工具守卫
IDE 集成 深度 VS Code/JetBrains 集成，LSP ACP 适配器（VS Code/Zed/JetBrains）
开源协议 部分开源（源码可见但有限制） MIT 完全开源
自托管 需要 Anthropic 账号 完全自托管，任意端点
研究用途 有限 批量轨迹生成，训练数据压缩
供应链安全 标准 npm 依赖 严格上界 + SHA 锁定策略

关键差异总结

Claude Code 是 Anthropic 为自家模型打造的精品 IDE 工具，TypeScript 全栈，IDE 集成深度无与伦比，权限系统极其精细。Hermes 是 Nous Research 为"模型无关、平台无关、自我进化"设计的完整 Agent 运行时，Python 核心更适合 AI/ML 生态，多平台覆盖和自我学习能力是其核心差异化。两者都用 Ink 构建 TUI，但 Hermes 的 TUI 通过 JSON-RPC 与 Python 后端通信，Claude Code 的 Ink 是完全自研的 TypeScript 实现。

07

为什么说 Hermes 是"有缰绳的"?

自由奔跑，但不失控 — Hermes 的控制哲学

核心理念

Hermes 的名字来自希腊神话中的信使之神，手持双蛇缠绕的权杖（Caduceus）。双蛇象征着两种力量的平衡：自主能力与可控边界。Agent 越强大，缰绳就越重要。

预算缰绳
IterationBudget 限制工具调用轮次（默认 90 次）。预算耗尽后有一次 Grace Call 让 Agent 优雅收尾，而不是无限循环消耗 API 费用。
中断缰绳
任何时候发送新消息或 /stop 命令都能中断正在运行的 Agent。父 Agent 被中断时，子 Agent 也会被取消。
危险命令审批
ToolGuardrails 检测危险命令（rm -rf、DROP TABLE 等），在执行前要求用户明确批准。
提示缓存不可变
系统提示在对话中不可变。技能/工具/记忆的变更默认延迟到下次会话，防止 Agent 在对话中途改变自己的行为边界。
Profile 隔离
每个 Profile 有独立的 HERMES_HOME，配置、密钥、记忆、会话完全隔离。一个 Profile 的 Agent 无法访问另一个 Profile 的数据。
Cron 硬中断
Cron 会话有 3 分钟硬中断限制，防止定时任务中的 Agent 失控循环占用调度器。
DM 配对安全
消息平台上的用户必须先完成 DM 配对才能与 Agent 交互，防止未授权用户控制 Agent。
供应链缰绳
所有 PyPI 依赖有上界版本，Git 依赖锁定到 SHA，GitHub Actions 锁定到 commit SHA。这是 litellm 供应链攻击事件后建立的政策。
插件不得修改核心
插件 MUST NOT 修改 run_agent.py、cli.py、gateway/run.py 等核心文件。需要新能力时扩展插件接口，而不是硬编码。
